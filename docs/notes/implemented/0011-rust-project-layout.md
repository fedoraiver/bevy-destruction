# ADR 0011：Rust 模块与测试布局

## 状态与日期

2026-11-17 采用并实现，目录迁移对应提交 `1ec85cb`。二进制入口的初始布局随后由 [ADR 0016](0016-shared-schedule-export.md) 调整，现行 workspace 与应用入口见 [ADR 0019](0019-workspace-app-entrypoints.md)。模块和测试的目录规则继续沿用，功能目录内的实现拆分约定见 [ADR 0027](0027-src-module-responsibilities.md)。

## 背景

运行时模块曾平铺在 `src`，测试分散在实现文件末尾和多个独立文件。随着几何、结构求解和诊断功能增加，同一个模块的实现与回归需要稳定的入口。

## 决策与实现

- 初始布局以 `src/main.rs` 为二进制入口。其余模块使用 `src/<module>/mod.rs`，保留 `crate::<module>` 导入路径。
- 单元测试和仅供测试使用的辅助函数放入同目录的 `tests.rs`，实现文件通过 `#[cfg(test)] mod tests;` 引用。按主题分组的测试可在 `tests.rs` 内使用子模块。
- 随迁移更新 `include_str!` 等相对路径，保持资源位置、资产根目录和测试的私有访问范围。资源版本迁移按 [ADR 0005](0005-v2-asset-contract.md) 独立验证。

## 备选方案与取舍

继续平铺文件的迁移成本最低，模块目录使实现与回归位置稳定。顶层集成测试适合公共接口；模块内单元测试可以直接验证求解器和生命周期的私有实现。

## 验证要求与已完成验证

迁移检查编译、格式、路径解析和原有回归。迁移阶段的 100 项 Rust 测试通过；同轮资产格式变更有自己的回归证据。

## 未决问题

新增模块和测试按此布局组织。公共库接口及其集成用例在需要时另行设计。
