# ADR 0020：从桌面游戏包导出 ECS 架构

## 状态

2026-11-23 采用并实现。替代 [ADR 0019](0019-workspace-app-entrypoints.md) 中的独立架构分析包。

2026-11-28 明确桌面文件设置与架构导出的装配入口。

2026-11-29 将桌面功能插件装配移入 `build_app()`，无窗入口独立声明功能插件。

## 背景

架构分析和桌面入口先前分别装配 Bevy，并通过两个 Cargo 包编译同一份插件源码。分析结果应反映桌面入口实际安装的插件和调度。

## 决策与实现

工作区元数据选择 `apps/game` 的 `bevy-destruction` 包，包元数据指定 `build_app`。游戏库的 `build_app()` 直接安装桌面窗口和 `src/` 中的功能插件，并使用内置的 `DemoSettings` 默认值，使不同机器能按同一配置导出调度。桌面入口在此基础上安装原生设置插件，从系统偏好目录读取用户设置，并在运行前应用开关。无窗入口独立读取用户设置并安装功能插件。[工作区元数据](../../../Cargo.toml) · [桌面包元数据](../../../apps/game/Cargo.toml) · [装配入口](../../../apps/game/src/lib.rs) · [桌面启动](../../../apps/game/src/main.rs) · [无窗装配](0026-python-driven-acceptance.md)

## 备选方案与取舍

独立分析包便于试验不同配置，但需要维护单独的清单和条件编译。将导出入口放在桌面包，可共用实例化路径。导出函数成为库入口的一部分，适配 bevy-cicd 要求的无参 App 入口。

桌面与无窗入口各自列出所用插件，无窗入口可就地配置离屏条件。新增功能插件时需要同步两处装配。

## 验证要求与结果

确认 Cargo 仍默认选择桌面应用，无窗包可使用 `acceptance-test` 编译。验证共享导出器选择桌面包，获取主应用和渲染子应用调度，并能检查生成的架构站点。

初次迁移时已检查锁定的 Cargo 元数据、桌面选项与无窗构建。该次共享启动器的运行快照包含主应用、RenderApp 和 RenderExtractApp 的 27 个调度。主应用的固定步含刚体簇重建系统。

入口改为直接装配后，再次运行共享启动器，导出了主应用、RenderApp 和 RenderExtractApp 的 27 个调度。固定步包含刚体簇重建和应力系统，更新调度包含暂停菜单和场景重载系统。
