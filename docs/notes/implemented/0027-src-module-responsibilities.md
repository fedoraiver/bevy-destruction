# ADR 0027：按职责拆分功能目录

## 状态与日期

2026-11-29 采用并实现。在 [ADR 0011](0011-rust-project-layout.md) 的模块与测试布局上补充功能目录内部的组织方式。

## 背景

随着暂停菜单、场景加载、物理求解和渲染诊断扩展，多个功能的 `mod.rs` 同时承担插件装配和大量实现。阅读调度时需要在实现间跳转，修改单项职责时也要定位到同一个长文件。

## 决策与实现

- 功能目录以 `mod.rs` 声明子模块、装配插件并管理导出。职责独立的实现平铺在同一目录。暂停菜单分别维护视图、输入和重载，撞击物分别维护发射、接触和两条断裂路径。[菜单入口](../../../src/menu/mod.rs) · [撞击物入口](../../../src/projectiles/mod.rs)
- 通过直接重导出保留调用入口和系统调度依赖。反射类型保留原声明位置，使无窗验收使用的完整类型路径稳定。架构导出中的系统全名随函数所在子模块更新。
- 现有测试文件与夹具保持原样。实现移动后，原有测试通过父模块的测试专用导入访问所需类型和函数。

## 备选方案与取舍

原有单文件布局便于查找小而集中的功能，继续用于边带轮廓、受力样本和结构连通性等模块。跨功能统一建立组件、系统和资源目录会分散单项功能的维护入口。按职责拆分保留局部上下文，代价是增加少量同目录导入和导出。

## 验证要求与已完成验证

- 核对了原有调度、反射类型路径及 23 个测试与夹具文件。格式检查、Clippy 和 143 项 Rust 测试通过。
- 启用 `acceptance-test` 的 release 构建通过。默认无窗矩阵通过 18 项，共 19 项。`force.break_and_clear` 在本次重构和 `6ac677b` 基线均报出同一断言错误。临时将查询限定到碎块的直属网格后，受力用例通过，残留的值 1 和 2 均来自建筑网格之外。
