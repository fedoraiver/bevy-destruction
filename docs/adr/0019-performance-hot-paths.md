# ADR 0019：求解热点、撞击输入复用与烟尘渲染性能

## 状态

- CPU 热路径决策已采用并实现，冻结输入对照和合并 Rust 回归已完成。
- 日期：2026-11-17。
- 本记录先覆盖 CPU 热路径；烟尘共享缓冲的实现和图形测量单独追加，不能由 CPU 求解计时推断整帧收益。
- 补充 [ADR 0015](0015-structural-and-collision-runtime-performance.md)、[ADR 0016](0016-damaged-structure-solver-and-support-release.md) 和 [ADR 0017](0017-progressive-impact-unloading.md)。

## 背景

受损窄支撑的稳健求解和逐连接撞击卸载已实现。继续优化时，需要区分结构组装、迭代矩阵乘法、精确残差、应力恢复、重复输入准备和实际渲染成本。完整游戏与隔离程序的代码布局、负载不同，不能混合其绝对耗时计算加速比。

本轮保持资产划分、逻辑 Chunk 数、碰撞代理、材料、强度、撞击时标、固定步和断裂规则。求解仍使用 f64、`1e-8` 相对残差、3000 次总预算及 512 次普通 PCG 后的稀疏分解/补偿修正路径。每次断开一个动态连接后仍重新求解；分离后仍释放原冲击事件。

## 已采用并实现的 CPU 决策

### 跳过 Jacobian 中精确为零的系数

六自由度 Jacobian 含大量结构性零项。补偿应变计算此前对每个稠密槽位都执行乘法、FMA 误差恢复和补偿累加；现在仅跳过 `coefficient == 0.0` 的项，保留其余项的次序。补偿位移低位、真实单元内力残差与应力恢复继续使用同一计算路径。

没有引入近零阈值、降低数值精度或移除微小的非零几何项。冻结输入对照用于确认这项改动保持当前实际资产的输出位模式。

### 按冲击事件保存不随断键变化的输入

`ClusterImpact` 现在持有可选 `PreparedImpact`，保存一次计算的惯性平衡节点载荷和 f64 截面顶点表。

- 同一冲击事件的成员和原始接触冲量保持不变时，内部连接逐个断开只改变连接图；上述准备数据可供后续求解复用。
- 首次准备截面表时以 `BTreeSet` 检查成员，替代对每个 ContactPatch 两端反复线性扫描 Chunk 列表。
- 每次处理仍先验证成员存活、成员数量及所属刚体。成员失效或出现多个刚体时，先丢弃/释放原事件，再决定是否使用准备数据；原冲量不分摊给新子簇。
- 事件完成、失效、分离或重置时，准备数据随事件释放。各事件独立保存输入；资产及接触几何在实例生存期内保持不变，沿用 ADR 0015 的设定。
- 首次准备仍有成本。后续每次连接变化仍调用求解器并使用当前有效连接，没有复用旧内力或断裂名单。

## 冻结输入的 CPU 测量方法

对照使用同一机器、`rustc 1.99.1 (58cf8f9c3 2026-10-13)`、`opt-level=2`、`debuginfo=1` 和相同已编译依赖。该工具链以并存方式安装，没有切换全局默认或为此重编译全部 Bevy。计时副本只增加阶段计时器，基线求解源码 SHA-256 为 `474dcb26ceab7bdb6960e26629aea4ccf0a4db5803e83c38477c6d8fce2ec58a`。

隔离程序读取真实清单和 GLB，生成相同 ContactPatch/截面数据。测量包括：

- 完整板楼 455 块、L 形高楼 433 块、桥梁 71 块、矩形 255 块的自重求解。
- 板楼质心高度不低于 16 m 的 236 块上部结构。对其中质心低于 16.3 m 的底层碎块均分沿 `+Y` 的总冲量 `2e7 Ns`，质心冲量矩为零，按现有 10 ms 时标生成惯性平衡载荷；重力输入为零，使用排序后首节点的数值约束。
- 动态样本在同一事件中每次只停用当前最高承载率连接，检查仍连通后，冻结第 0、3、6、9 次断键后的输入。第 9 次断键后的样本触发 512 次后的稳健求解路径。

每个样本运行 12 次，前 2 次预热，记录其余 10 次的中位数。对照批次交替运行基线、单独零项优化、候选矩阵实现、零项优化加准备数据复用、基线；期间没有同时运行 Blender、游戏或其他 CPU 测试。下表基线取前后两个基线批次中位数的中值。

阶段计时覆盖输入准备、校验、组装、PCG、PCG 内的矩阵乘法/预条件/单元残差/分解，以及应力恢复。动态续步表中的缓存准备在首次事件建立时完成，因此“优化后”对应已准备事件的后续求解，不代表首次接触的冷启动耗时。

### 热点定位与阶段收益

首次定位批次中，完整板楼总用时约 `22.59 ms`：PCG `17.50 ms`，其中稀疏矩阵乘法 `10.73 ms`、预条件 `2.83 ms`、补偿物理残差 `0.63 ms`；组装 `3.36 ms`、恢复 `1.06 ms`。矩阵乘法仍是主要计算热点。

只加入精确零项跳过后的同输入阶段对照如下，单位为 ms：

| 样本 | 物理残差：基线 → 优化 | 应力恢复：基线 → 优化 |
| --- | ---: | ---: |
| 完整板楼 | 0.635 → 0.323 | 1.077 → 0.750 |
| 完整 L 形高楼 | 0.610 → 0.307 | 1.025 → 0.707 |
| 上部结构，第 9 次断键后 | 1.415 → 0.482 | 0.916 → 0.448 |

动态输入准备在基线中每次约花费 `0.10–0.11 ms` 计算惯性载荷、`0.63–0.68 ms` 构造截面表。准备数据复用消除续步中的这两项重建工作。零项优化和准备数据复用合并后的隔离续步总用时如下：

| 236 块上部结构样本 | 基线 ms | 优化后 ms | 迭代数，两侧相同 |
| --- | ---: | ---: | ---: |
| 初始连接图 | 11.730 | 10.241 | 425 |
| 第 3 次断键后 | 11.895 | 9.856 | 433 |
| 第 6 次断键后 | 11.446 | 10.670 | 446 |
| 第 9 次断键后 | 17.564 | 14.608 | 513 |

CPU 频率、缓存状态与代码布局仍使总用时产生波动。阶段收益比小幅总耗时差更稳定；不据此声称每种建筑具有固定比例的整体加速。这些是冻结输入的单次 CPU 工作量，不含 ECS、接触物理、烟尘和渲染，不能换算为游戏 FPS。

隔离脚本、阶段原始数据和逐 Bond 输出位于本机忽略目录 `output/perf-hotpaths/`，其中 `prepare.py`/`main.rs` 记录输入构造，`base-c.jsonl`、`base-d.jsonl`、`zeros-c.jsonl`、`cached-c.jsonl` 记录上述批次。该目录不属于正式运行时或提交产物。

## 备选方案与取舍

- 对矩阵块改用列存储、独立行累加和显式六行展开，均保持了冻结输入的输出指纹，但未获得可重复的矩阵乘法收益，部分动态样本变慢。本轮保留既有 CSR 布局，采用更局部且已测得阶段收益的改动。
- 缓存惯性载荷和几何输入比缓存旧解更容易界定有效期：内部连接变化时准备数据仍有效，内力解必须更新。完整矩阵增量更新、预条件器复用和更广泛的 SIMD/并行路径需单独测量、验证。
- 事件缓存增加与该事件成员数、截面顶点数相关的内存，换取多个续步的准备时间；生命周期随原事件，避免长期保留失效成员的数据。

## 已完成验证

- 八个冻结样本的已保存逐 Bond 输出在五个对照批次中逐字节一致；界面力/力矩、拉压剪应力、承载率及支撑反力的 f64 位模式指纹一致，迭代数和报告残差也一致。
- 修改后的动态落地、不同落高、数值约束/平衡和受损窄支撑回归均已通过；完整工作区结果随烟尘优化的独立记录追加。
- 分离生命周期测试先准备并求解一个有效冲击事件，再改变真实拓扑拆开成员；后续处理释放已有事件，连接状态不受原冲量再次影响。
- 数值稳健性仍由 ADR 0016 的独立节点/总力矩平衡、稠密参考和真实受损图回归约束；本轮没有修改其验收精度。

## 未决问题

CSR 矩阵乘法仍占求解的大头；复杂接触、边带网格生成和烟尘渲染也可能形成长帧。后续优化应继续固定输入、拆分 CPU/GPU 阶段并验证输出，避免用改变破坏规模替代热点优化。
