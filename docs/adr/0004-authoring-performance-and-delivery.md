# ADR 0004：资产制作、性能边界与分阶段交付

- 状态：提议（待原型验证）
- 日期：2026-11-16
- 关联：[ADR 0001](0001-prefractured-graph-and-clusters.md)、[ADR 0002](0002-avian-backend-and-fixed-step.md)、[ADR 0003](0003-structural-loads-and-progressive-fracture.md)

## 背景

项目目标是接近 THE FINALS 的建筑实时物理破坏。必须先验证局部破坏、承载重分配、坍塌、碰撞和二次破坏形成完整闭环，再讨论大规模渲染与联网。

GDC 2024 讲稿展示了 Houdini 预破碎、连接生成、渲染变换池以及网络快照压缩等内容。这些是参考原则，不能把原游戏的带宽示例或求解器表现作为本插件的性能承诺。

## 决策提议

### 首轮范围

以单机 PC 的一栋三层框架楼为首轮验收场景。楼体由可破坏墙体、梁柱和楼板组成，具备真实破口、碰撞更新、载荷重分配、残骸坠落和二次撞击。

三层、单机和 PC 是用于限制初始验证成本的候选设定。目标硬件、建筑尺寸、结构块数、同时活跃刚体数与可接受耗时尚未确定，不能从本记录推导出已验证的运行规模。

### 资产制作与导入

1. 原型阶段先程序生成规则墙体、梁柱、楼板及明确的连接数据。
2. 后续接入 Blender 或 Houdini 制作的预破碎资产，候选交换格式为 glTF 网格加独立结构描述文件。
3. 描述文件保存格式版本、稳定碎块 ID、局部变换、质量属性、凸碰撞体、连接界面、材料和锚点；格式细节在导入实现前另行确定。
4. 连接生成依据真实接触面或明确的制作标记，支持人工添加、禁用和调整强度。不能只用中心距离决定相邻碎块是否焊接。
5. 资产工具应校验缺失网格、重复 ID、无效连接、非法质量、孤立碎块和错误锚点；允许合理的装饰或独立部件显式声明为非承载。

预破碎决定可用断面，运行时玩家行为决定损伤与运动。首轮不以任意运行时网格切割为前提。

### 表现与性能边界

- 结构节点、显示碎片和刚体数量允许不同。关键墙块、楼板和大型残骸保留真实碰撞；小碎屑按表现需求分级处理。
- 网格、断面显隐、粒子和声音由结构变化驱动；显示不强制与物理实体一一对应。
- 先使用 Bevy 常规渲染并测量 CPU 提交、绘制与变换上传开销，再决定是否实现 GPU 变换池或专门的碎块渲染路径。
- 休眠、碎屑寿命和模拟降级应有显式规则。影响承载或玩法碰撞的结构不能因显示降级而被悄悄删除。
- 仅重新处理发生变化的结构分量；分量内的载荷仍需全局重分配，不能把计算范围简单截在爆点附近。
- 固定步进设置连锁断裂轮次和工作预算，保留未完成任务，避免同步递归处理整栋建筑。预算截断必须可观测。

至少统计结构节点数、连接数、活跃刚体数、碰撞体数、接触对数、结构求解残差与迭代数、拓扑处理耗时、碰撞体/质量属性重建耗时，以及帧时间中位数、高分位和峰值。

### 保存与联网边界

核心数据保留资产版本、稳定碎块/连接 ID、实例 ID 与拓扑修订标记，为状态保存、事件重放和后续联网提供依据。具体序列化格式与兼容策略另行决定。

多人方案候选为权威端决定连接断裂和关键残骸运动，客户端接收结构变化与关键刚体快照。先明确全量状态、增量状态和重同步，再逐步加入量化、增量压缩与相关性裁剪。暂不以跨平台确定性锁步为假设。

### 分阶段交付

| 阶段 | 交付内容 | 验收场景 |
| --- | --- | --- |
| P0 | 直接伤害、断连接、拆簇、刚体坠落、调试显示 | 桥段断开后坠落；旋转簇拆分保持位姿与速度场；质量和动量检查 |
| P1 | 锚点、自重、六自由度连接承载、过载断裂 | 悬臂承载；多支点分担；去掉支柱后重新分配并在过载处失效 |
| P2 | 接触冲量映射、动态簇再碎裂、二次破坏 | 自由落体不因错误自重载荷自碎；落地撞碎；楼板砸坏下层 |
| P3 | 损伤累积、弱连接、挂接与最终断开 | 楼板先倾斜挂住，再因连接失效坠落 |
| P4 | 资产导入、规模测试、休眠与碎屑分级、渲染优化、保存及联网接口 | 多栋建筑连锁破坏；性能瓶颈和降级行为可量化 |

首轮建议完成 P0 至 P2 及三层楼演示。P1 是承载路线的关键验收：仅凭直接伤害删边和无支撑簇下落，不能宣称已经实现结构承载分析。

## 备选方案与取舍

- **先做任意运行时切割**：能提高破口自由度，但同时增加网格、碰撞与连接重建复杂度，延后核心承载验证。
- **先制作高精度建筑与完整特效**：容易让资产成本掩盖结构模型问题；先用规则测试资产更便于定位错误。
- **一开始优化专用渲染或完整联网**：缺少实际负载与行为基准，容易优化错误对象；保留数据边界并分阶段引入。
- **所有碎片都独立模拟**：实现直观，但刚体、接触、调度与同步成本随碎片增加；采用结构、物理、表现分辨率分离。

## 验证与未决问题

- 所有交付阶段尚未开始实施，本记录不代表测试已通过。
- 目标硬件、目标规模、具体性能预算与最低稳定步长需要原型数据确定。
- 需验证预破碎断面显隐、薄墙碰撞、跨部件连接生成，以及外部资产工具的可重复导入。
- 需在固定场景中记录平均与峰值耗时，单独测量最大连通图、集中拆簇和落地接触高峰，不能只展示平均帧率。
- 多人同步涉及玩家与残骸交互；权威纠正、插值、断线重入和状态版本需要后续专门 ADR。
