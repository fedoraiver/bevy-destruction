# ADR 0022：Rust 模块目录与集中测试布局

## 状态

- 日期：2026-11-17。
- 用户明确要求，已采用并完成目录迁移；机械迁移后的编译与 100 项回归已通过。
- 本记录描述目录组织。旧版资产兼容移除由对应资产决策及后续实现记录，不与机械移动混为同一变更。

## 背景

此前运行时模块平铺在 `src`，测试既有文件末尾的内联模块，也有 `*_tests.rs` 和单独的坍塌测试文件。继续增加几何、物理与调试功能时，同一个模块的实现和测试位置不统一。

## 决策

- `src/main.rs` 保留为二进制入口。其余模块统一为 `src/<module>/mod.rs`，模块名和 `crate::<module>` 导入路径保持不变。
- 每个模块的单元测试统一位于 `src/<module>/tests.rs`，实现文件仅保留 `#[cfg(test)] mod tests;` 声明。
- 同一模块的多个测试主题可在该 `tests.rs` 中使用内联子模块隔离辅助函数和导入，不再分散为其他测试文件。
- 仅供测试使用的辅助函数也移至对应 `tests.rs`；不为目录调整扩大运行时接口的可见性。
- `include_str!` 等相对路径随源文件深度调整。资产根目录、命令行、物理参数和运行时行为不由此次移动改变。

## 备选方案与取舍

- 继续平铺、按文件名区分测试：移动成本最低，但不符合用户要求。
- 统一到顶层 `tests/`：适合只依赖公开 API 的集成测试；现有求解器和生命周期回归需要访问模块私有实现，因此本轮采用模块内 `tests.rs`。
- 为每个测试主题再建文件：会继续分散同一模块测试，本轮使用一个文件内的测试分组。

## 实现与验证

- 已迁移 23 个原有实现模块，并集中 16 个模块的测试。另有正在接入的 3 个受力显示模块与 2 个测试模块沿用同一布局，随对应功能独立提交。
- 已检查 `src` 顶层仅保留 `main.rs`，测试函数仅出现在各模块的 `tests.rs`。
- `cargo +1.99.1 test -- --nocapture`：100 项通过，0 失败，测试部分耗时 4.45 s；迁移前后测试数量一致。
- `cargo +1.99.1 fmt --check` 通过。
- 严格 Clippy 已运行；报告受力显示中的可合并条件和折面测试中的索引循环两项既有告警，未发现目录或路径迁移错误。这两项由对应功能负责人处理，不能将本记录视为最终全工作区静态检查已通过。

## 未决问题

后续新模块和新测试须沿用该布局。现有受力显示、新分块及资产格式变更仍按各自决策记录独立验证，不能以目录迁移检查替代其功能验收。
