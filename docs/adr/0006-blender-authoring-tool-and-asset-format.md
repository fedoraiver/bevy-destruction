# ADR 0006：Blender 资产工具与导出格式

- 状态：已采用（正在实现，验证进度另行记录）
- 日期：2026-11-16
- 关联：[ADR 0005](0005-blender-procedural-building-pipeline.md)、[ADR 0001](0001-prefractured-graph-and-clusters.md)

## 背景

用户要求开始开发 Blender 资产工具。需要将此前的局部几何实验扩展为可使用、可重生成、可验证和可导出的资产制作流程。运行时破坏插件仍属独立工作范围。

## 决策

- 在 `tools/blender/bevy_destruction` 实现 Python 工具包，提供 Blender 面板和后台命令行入口；不依赖 computer-use、付费插件或用户场景中的临时选择状态。
- 以 Blender 5.2 LTS 为实际验证环境；使用原生 Python/BMesh 构造几何，不将尚未核验的社区建筑或破碎扩展作为必需依赖。
- 输入由闭合平面外轮廓、可选庭院/内墙、楼层和墙厚参数、显式门窗标记、材料及破碎种子构成。无效几何或不支持的参数必须明确报错。
- 先生成互不重叠的封闭凸构件，再执行带固定种子的 Voronoi 预破碎。每个输出碎块保留源构件 ID；凸性保证允许逐碎块生成真实凸碰撞代理，避免凸包填平开口。
- 从实际共面接触面的重叠区域构造 Bond，保存面积、位置和法线；不能仅按中心距离连接。导出锚点、体积、质量、质心及惯性张量。
- 导出 GLB 与版本化 JSON 结构清单。GLB 中保存碎块显示网格及稳定 ID；JSON 保存碰撞顶点、连接和物理数据。资产采用米、右手系、Y-up，Blender 坐标 `(x,y,z)` 转换为 `(x,z,-y)`，与 glTF 输出保持一致。
- 相同输入、种子与工具版本应产生相同的结构 ID 和拓扑摘要。拓扑改变使用资产内容标识区分，不承诺跨任意重建保留所有碎块 ID。
- 重生成只替换本工具拥有的建筑集合，保留用户其他物体；失败时保留上一次成功结果。导出不要求把当前场景清空。

## 备选与取舍

Geometry Nodes 预览可以后续接入同一数据流程。当前先采用可批处理的 Python 几何路径，便于同时验证门窗、封闭性、凸性和导出数据。完整弹性求解、动态坍塌、联网及 Bevy 导入器不在资产工具内部实现。

## 验证

必须实际覆盖矩形、L 形、多层、庭院/内墙及门窗资产，检查封闭体、体积守恒、碰撞洞口、接触连接、锚点连通性、固定种子重建，以及 GLB/JSON 对应和坐标。面板注册、曲线/网格输入、后台构建和重复执行需有验证证据；最终支持范围与限制在工具说明中明确记录。
