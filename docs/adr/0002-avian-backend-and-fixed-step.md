# ADR 0002：Avian 物理后端与固定步调度

- 状态：提议（待原型验证）
- 日期：2026-11-16

## 背景

本项目拟实现面向 Bevy 的建筑实时物理破坏插件。结构图决定连接是否断裂以及如何拆簇，物理后端负责簇之间的运动、接触和碰撞。完整刚性簇内部不应依靠大量刚体关节维持形状。

调研时项目尚未添加 Bevy 或物理后端依赖。Avian 官方兼容表列出 Bevy 0.20 与 Avian 0.8 配套；此组合是候选基线，尚未完成编译、行为或性能验证。Avian 提供 ECS 原生的刚体、复合碰撞体、接触冲量、质量属性和固定步调度接口，适合先验证破坏管线所需的集成方式。

物理后端能够报告外部接触，却不能直接给出一个刚性簇内部各 bond 的反力。尤其对于仍与地基连接的静态建筑，不能只等碰撞事件来判断承载失效：结构层仍须根据自重、外部载荷和连接关系独立求解。

## 决策提议

### 依赖与接入边界

1. 首个原型采用单后端，候选组合为 Bevy 0.20 + Avian 0.8；添加依赖时选择可兼容的已发布版本，并通过锁文件固定原型运行环境。
2. 首版仅实现 Avian 接入模块，不同时实现 Rapier，也不先构建通用物理框架。
3. 结构资产、稳定的 chunk/bond/cluster 标识和结构求解结果不依赖 Avian 的组件类型。薄接入层只负责刚体生命周期、碰撞体归属、位姿与速度、质量属性、冲量和接触采样。
4. 优先使用公开接口。Avian 自定义 XPBD 约束接口属于高级接口，官方提示其可能发生较大变更；如后续需要松散连接，应在小规模原型中另行验证。

### 刚性簇与碰撞体

- 每个仍完整连接的刚性簇对应一个刚体，而不是每个 chunk 都始终对应一个独立动态刚体。
- 用凸碰撞体组合表示簇。Avian 支持 `Collider::compound`，也支持将多个 Collider 实体挂在同一刚体下。
- 原型优先使用可识别的子 Collider 实体，以便把接触位置与冲量映射回 chunk。若改用单个 compound Collider，必须先验证能否可靠恢复被命中的 chunk，不能假定 compound 的子形状标识自动等于 chunk 标识。
- 动态残骸优先使用凸包或凸分解后的组合。动态凹三角网格不作为默认方案；碰撞近似的精度、生成成本和数量上限需随资产规模测试。
- 子 Collider 数量仍会影响接触检测成本，不能仅以刚体数量减少作为性能结论。

### 拆簇状态转移

拆分前记录旧簇的世界位姿、质心、线速度和角速度，计算新簇成员及局部坐标后统一提交：

1. 保持各 chunk 的世界位姿连续。变更父实体或刚体归属时重新计算局部变换，避免直接沿用旧的局部变换。
2. 从成员的质量属性重新计算每个新簇的质量、质心和惯性。显式质量属性与后端根据 Collider 计算的属性需要选择一致的来源，避免重复计入质量。
3. 对来自运动刚体的新簇，继承旧刚体的速度场。以世界坐标计算：

   ```text
   v_new = v_old + omega_old × (c_new - c_old)
   omega_new = omega_old
   ```

   其中 `c_old`、`c_new` 为旧簇和新簇的世界质心。对自由运动簇的全部拆分结果，应验证质量、线动量与角动量的数值误差；静态锚定结构转为动态时须明确与世界支撑的边界条件。

4. 在新簇质量属性和速度初始化完成后施加新的爆炸等外部冲量，同一冲量只施加一次，不再向旧簇重复施加。
5. 已由物理后端求解过的碰撞冲量仅作为结构损伤和载荷输入，不再次作为外部冲量施加，避免能量重复注入。

自动质量重算是后端已有能力，但组件归属变化、质量重算和刚体初始化的具体生效顺序仍须原型验证。

### 固定步与拓扑提交

初始目标为 60 Hz 固定物理步；这是原型参数，不是已经验证的性能承诺。结构更新与物理步共享固定时间基准，渲染显示使用插值。

每个固定步采用以下顺序：

1. 读取前一个物理步缓存的接触反馈，并收集本步爆炸、直接伤害和其他外部输入。
2. 更新受影响的结构图，求解载荷、判定断键并生成拆簇计划。
3. 在物理求解器之外统一提交拓扑变化，完成 Collider 归属、世界位姿、质量属性和速度初始化，再施加本步新增外部冲量。
4. 运行本步物理模拟。
5. 在后端写回完成后采样接触数据，缓存供下一个固定步使用。

Avian 默认在 `FixedPostUpdate` 运行物理，也允许自定义调度。实际集成必须显式安排系统先后顺序，并确保延迟命令和质量重算在本步物理准备阶段前生效；不能仅依赖系统注册顺序。不得在接触或约束求解过程中修改刚体和 Collider 拓扑。

接触反馈延迟一个固定步是首版的集成选择。若后续需要更紧密耦合，应另行评估收益、调度复杂度和重复求解风险。

## 备选方案与取舍

### Rapier

`bevy_rapier3d` 0.37.0 的已发布包依赖 Bevy `^0.20` 和 Rapier `^0.36.1`，可作为同一 Bevy 主版本下的备选。它提供复合刚体、接触力事件、固定调度等能力；接触力事件需要启用对应事件标志和阈值。

选择 Avian 的理由是 ECS 集成方式和模块化接口适合当前插件原型，而非已证明其性能或稳定性优于 Rapier。只有在相同建筑资产、活跃刚体数、Collider 数和模拟参数下进行比较，才能作出性能判断。如果 Avian 在拆簇生效顺序、接触采样或目标场景稳定性上无法满足需求，再以同一验证场景评估 Rapier。

### 每个 chunk 一个刚体并用固定关节连接

这种方案容易直接观察局部关节，但完整建筑也会产生大量刚体和约束，改变求解成本及稳定性问题。首版采用刚性簇聚合，把内部承载交给结构层。少量跨簇松散连接可作为后续能力，不据此恢复整栋建筑的逐碎块关节网络。

### 自定义底层物理求解器

首版不采用。建筑结构载荷求解与刚体接触求解分别承担不同职责，先建立可测量的闭环，再决定是否需要更深的后端扩展。

## 验证与未决问题

以下均为待完成验证，本文不代表已经通过编译、行为测试或性能测试。

- 验证 Bevy 0.20 + Avian 0.8 的实际依赖解析和最小场景编译，确定具体发布版本与所需功能开关。
- 验证子 Collider 换属、旧刚体移除、新刚体创建、质量重算及渲染变换的同一步一致性，排除一帧重叠碰撞体或过期质量属性。
- 验证拆分前后世界位姿连续、速度场继承正确，以及自由运动簇的质量和动量误差；分别覆盖静态锚定簇释放与动态簇再拆分。
- 验证外部冲量仅施加一次，碰撞反馈不会再次注入已求解的冲量。
- 核对接触冲量的采样阶段、方向和时间范围，尤其是开启多个 substeps 时返回值代表整个固定步还是单个子步，以及应如何累计。不得在未确认范围时直接把返回值除以固定步长当作力。
- 确认静止支撑接触与新冲击的区分方式，避免持续接触在每步被重复视作独立撞击损伤。
- 验证接触 Collider 到 chunk 的稳定映射，以及复合形状、睡眠与唤醒后映射是否仍正确。
- 用薄墙、高质量比、残骸堆叠、快速撞击和连续拆簇场景检查稳定性与 CCD 行为。
- 分别记录结构求解、拓扑提交、质量重算、碰撞检测和接触求解成本，并同时报告活跃刚体数及 Collider 数，避免只统计平均帧率。
- 决定 substeps 数量、碰撞体复杂度和动态残骸上限；初始 60 Hz 不预设这些参数已经满足目标。
