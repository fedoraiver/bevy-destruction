# ADR 0001：预破碎资产、结构连接图与刚体簇

## 状态

- 部分已采用（刚性连接图、固定锚点与动态簇已实现，验证范围见 ADR 0009）
- 日期：2026-11-16
- 更新：2026-11-17
- 三层分工、稳定 Chunk/Bond 身份、刚性连通分量合簇、完全固定锚点及失支撑动态转换已采用并实现，具体边界见 [ADR 0009](0009-support-release-and-dynamic-clusters.md)。弱连接、独立承载求解、接触驱动二次破坏等条目仍为提议。实现与已完成验证分别记录，不由本文状态推定全部验证通过。

## 背景

项目目标是在 Bevy 中实现接近《THE FINALS》体验的建筑实时物理破坏：局部损伤能够改变承载关系，失效部分可以脱离、运动并造成二次破坏。本文最初形成时尚无破坏系统；截至 2026-11-17 已在静态局部破坏基础上实现失支撑分量的刚体下落，尚未实现承载求解和接触驱动二次破坏。

预先切分几何只决定潜在的断裂边界，不预先决定某次坍塌的时间、断裂顺序和运动轨迹。若将每个视觉碎片始终作为独立刚体，会过早把全部成本交给接触与约束求解；若始终把整栋建筑作为一个刚体，又无法表达局部脱离。

GDC 演讲和本地笔记为本方案提供了预破碎、连接关系、破坏判定和求解器方面的参考。本文的类型划分、资产格式、状态机与合簇规则属于本项目的设计提议，不声称复现演讲中的完整内部实现。

## 决策提议

采用三层分工，并通过稳定标识关联数据：

| 层次 | 主要责任 | 不应隐含承担的责任 |
| --- | --- | --- |
| 几何与表现 | 预破碎网格、断面材质、可见性、细碎屑与特效 | 用视觉碎片数量决定结构节点或活跃刚体数量 |
| 结构 | Chunk、Bond、Anchor、损伤、承载和拓扑变化 | 直接代替刚体接触、碰撞与运动积分 |
| 物理 | Cluster 的质量属性、碰撞体、位姿和速度 | 仅凭刚体连通性推断连接仍有足够承载能力 |

### 基本概念

- **Chunk**：结构碎块，是质量、结构载荷和几何关联的基本单位。初期可以采用一个结构 Chunk 对应一份预破碎网格及碰撞代理的简单映射；后续允许一个结构 Chunk 关联多个纯表现碎片。
- **Bond**：Chunk 之间的连接。记录端点、连接位置与局部方向、界面面积、材料和强度等数据；承载求解所需的刚度与截面参数见 ADR 0003。
- **Anchor**：结构与永久支撑边界的关联，例如地基到固定世界。它需要明确约束的自由度，不能把任意接触点默认为永久锚点。
- **Cluster**：运行时沿刚性连接形成的连通分量，用一个刚体及复合碰撞表示其整体运动。Cluster 是可重建的派生结果，不能代替 Chunk/Bond 的持久身份。

### 资产与实例

不可变的破坏资产保存 Chunk/Bond 定义、局部变换、网格与材质引用、碰撞代理，以及体积、质量或密度、质心和惯性等质量属性。质量属性的唯一来源和计算约定需要统一，避免渲染、结构和物理层各自计算出不一致的建筑。

运行时实例保存损伤、连接状态、锚点激活状态、Chunk 所属 Cluster、动态位姿和待处理拓扑变化。多个实例共享同一资产，各自拥有独立状态；不直接修改共享资产来表达受损。

资产内的 `ChunkId` 和 `BondId` 应稳定，不能使用 Bevy 实体编号、容器遍历顺序或临时 Cluster 编号作为持久标识。运行时通过实例标识与资产内 ID 组合定位对象。资产需要版本或内容标识，以便存档、回放及未来网络同步检测不匹配。重新导出资产后的 ID 保留与迁移规则仍需验证。

### 连接状态与合簇

连接在概念上分为以下状态：

1. **刚性连接**：参与合簇；允许存在结构求解用的小变形，但物理表现仍视为一个刚体。
2. **弱连接**：自身不参与刚性合簇；当两侧属于不同 Cluster 时，通过允许相对运动的约束保持有限连接，例如松动、挂接或铰接。若两侧仍通过其他刚性路径处于同一 Cluster，单独削弱这条边不会产生额外的刚体自由度。
3. **断连接**：不再提供连接约束或结构承载，不参与合簇。

**只沿刚性连接计算 Cluster。**弱连接不能继续把两侧合为一个 compound，否则无法产生相对转动或松动。状态划分不代表初版即支持弱连接；初版可以只有刚性和断开两种实际状态，并在资产与接口中保留扩展位置。

弱连接的承载反馈、约束形式和彻底断开的规则需另行验证。单纯降低 Bond 强度、同时保留同一个刚体，不能声称已经实现可见的渐进松动。初版也不自动修复或重新焊接已断开的连接。

### 支撑与动态转换

初版 Anchor 按完全固定边界处理：永久锚定边界仍有效的刚性 Cluster，作为固定刚体表示；失去全部永久锚定边界的 Cluster 转为动态刚体。后续若引入仅限制部分自由度的锚点，必须同时调整物理表示，不能仍将其一律视为固定刚体。是否仍与地基连通只决定拓扑归属和候选运动状态，不能代替承载检查：仍连着地面的细柱也可能因过载断裂。

动态碎块与地面、建筑或残骸的接触由物理系统处理，不因接触自动生成 Anchor，也不因进入休眠而成为永久支撑。移动支撑、临时接触对承载的贡献和弱连接支撑属于后续范围。

拓扑变化后需要批量重建受影响 Cluster 的碰撞与质量属性，并保持 Chunk 世界位姿。拆分产生的新刚体应继承父簇的刚体速度场，包括质心偏移带来的线速度，避免凭空增加或丢失动量。相关变更必须在明确的物理步边界提交。

## 备选方案与取舍

- **每个碎块始终为独立刚体，并以约束连接**：容易直接表达相对运动，但完整建筑阶段就需要求解大量刚体、约束与接触。可用于小规模验证或局部弱连接，不作为默认表示。
- **始终保留整栋建筑的单个刚体**：表示简单，但局部断裂、分离和二次破碎受限。仅适用于未发生拓扑变化的阶段。
- **运行时任意切割或体素重建**：潜在断裂边界更自由，同时增加几何生成、碰撞更新、资产制作和同步复杂度。当前优先验证预破碎方案，之后再评估扩展。
- **预制坍塌动画或预模拟事件**：适合确定的大型演出，但不能单独满足根据实际受损位置和支撑状态产生物理坍塌的目标。

刚性合簇会隐藏弹性形变；固定 Cluster 在断裂前不会发生整体挠曲。该限制是初期方案的明确取舍，不能通过应力可视化掩盖。

## 验证与未决问题

- 验证墙、桥和多层结构中的局部断裂，只重建受影响 Cluster。
- 验证含旋转运动的拆簇，检查质量、质心、惯性、总线动量与总角动量的一致性。
- 验证失去锚点后能够下落、落地和休眠，且接触或休眠不会自动焊回世界。
- 验证同一资产的多个实例互不修改共享状态，稳定 ID 能跨实体重建定位原 Chunk/Bond。
- 明确跨建筑连接、移动支撑和永久世界锚点的资产表示。
- 评估结构 Chunk、视觉碎片和碰撞代理的分辨率，以及复合碰撞体重建的峰值成本。
- 弱连接引入后，需要重新验证 Cluster 拆分、约束生命周期和承载反馈的边界。
