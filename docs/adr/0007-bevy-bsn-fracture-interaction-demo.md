# ADR 0007：BSN 建筑导入、网格材质与点击破坏演示

- 状态：已采用（含自由视角修订，已实现并验证，实际范围见实施记录）
- 日期：2026-11-17
- 关联：[ADR 0002](0002-avian-backend-and-fixed-step.md)、[ADR 0006](0006-blender-authoring-tool-and-asset-format.md)

## 背景与需求

提出本方案时，Blender 工具已输出预破碎 GLB 与结构清单，Rust 端仍为初始工程。用户随后要求实施可交互演示：使用 BSN 语法导入建筑，外表面显示 0.2m 细格与 1m 深色粗格，固定正对建筑的相机，按 0 切换预破碎线框，左击按既定碎块删除局部网格，并产生烟尘、粒子和粗糙断面材质。

2026-11-17 用户追加要求将相机改为自由视角：WASD 移动、鼠标转向、Space 上升、Ctrl 下降。此要求替代原固定正视与正交投影设定；原实现及其验证记录保留在下方历史记录中。

本轮以静态建筑的局部点删演示为范围。连接、质量和锚点继续加载保存；结构承载、失支撑坍塌、刚体残骸和联网属于后续运行时能力，不能把本轮点删称为已实现结构失效。

## 版本事实与 BSN 边界

- 沿用已确定的 Bevy 0.20.x + Avian 0.8.x。
- Bevy 0.20 已支持 Rust 中的 `bsn!` / `bsn_list!`，`.bsn` 文件资产格式尚未实现。本方案中的 BSN 指宏语法，不生成无法加载的 `.bsn` 文件。
- Bevy 0.20 已切换到 WESL 着色器；采用 `.wesl` 扩展 PBR，不照搬旧版 Bevy WGSL 预处理写法。
- 0.20 的 glTF primitive 材质是 `Handle<GltfMaterial>`。如需保留基础材质参数，先通过官方 `standard_material_from_gltf_material` 转换，再构建自定义扩展材质，不能将该 handle 当作 `Handle<StandardMaterial>` 使用。

上述接口已通过本仓库实际编译和运行。入口固定 Bevy 0.20.0、Avian 0.8.0，锁文件固定实际 Bevy 子 crate 为 0.20.1；不再依赖浮动的补丁版本验证结论。

## 导入与实体组织

### 资产加载

新增 `DestructibleAssetLoader`，以 `.destruction.json` 为入口，校验格式、单位、引用 ID 和对应 GLB 的 SHA256，将 GLB 作为正式资产依赖。依赖完成后读取 `Gltf.named_nodes`，按 Chunk ID 定位 `GltfNode`、`GltfMesh` 及所有 primitive 的 mesh handle。

通过已加载依赖状态与待实例化队列驱动生成，不能只监听一次加载完成消息，否则先加载后创建的实例可能漏生成。加载失败应显示简洁错误，不实例化部分建筑。

### BSN 声明

用 `bsn!` 声明相机、灯光、建筑根、Chunk 和显示 primitive；动态碎块列表由 Rust 数据循环调用这些场景函数。数据清单继续使用 JSON，BSN 负责 ECS 场景组合。

```text
DemoRoot
  Camera：透视自由飞行，初次加载按建筑包围盒取景
  Lights：斜向主光 + 环境补光
  BuildingRoot：实例 ID、资产 handle、存活状态
    ChunkRoot：Chunk ID、位姿、静态 Collider
      RenderPrimitive：Mesh + 外表面 Grid 材质
      RenderPrimitive：Mesh + 内部断面材质
    ...
  VfxRoot：烟尘与装饰碎屑
  Hint：WASD 移动 · 鼠标转向 · Space/Ctrl 升降 · 左键破坏 · 0 线框
  Crosshair：锁定鼠标时的屏幕中央准星
```

Chunk 根只应用清单中的质心位置和旋转，primitive 子节点使用单位变换；直接读取 glTF mesh handle，不再叠加 GLB 节点位姿。资产已经是米制 Y-up，导入时也不能再次执行 Blender 坐标转换。

建立 `ChunkId -> ChunkRoot / 全部显示子实体 / Collider / debug 边` 的映射。一个 Chunk 可以有多个 primitive，删除必须以整个 Chunk 为单位。共享资产数据不修改，`Alive/Removed` 和连接失效位于实例状态中。

本轮每块使用可独立删除的静态碰撞代理；不启用重力坍塌或失去支撑后的连锁删除。后续刚体簇表示可以通过物理接入层替换。

## 资产表面语义补充

现有 GLB 的原始材料有 `bd_material_id`，Voronoi 新切面使用 `BD_DestructionInterior`；尚无稳定的表面角色。实际模型只有 POSITION/NORMAL，未提供 UV/TANGENT。

需要在 Blender 导出材质 extras 中增加 `bd_surface_role = exterior | fracture`，导入时分别绑定 Grid 与粗糙断面材质。物理材料 ID 仍从所属 Chunk 读取，避免共享内部材质掩盖 concrete/steel 等类别。

还需处理源构件之间的埋藏接触面：当前只标记 Voronoi 新切面，墙段与墙段、楼板分区与墙体之间的接触面仍可能使用外材质。为保证所有新暴露面都正确，需要在烘焙时根据真实共面接触补丁细分表面，将接触区域标为 fracture，未覆盖区域保留 exterior。不能把只部分接触的整个楼板面都标为内部面。

该步骤只做共面划分、三角化和材质语义，不移动物理边界；重新校验封闭性、体积、碰撞、连接与导出哈希。现有 Bond 仅保存面积、中心、法线和二阶矩，不能据此准确重建每个接触补丁，分类时需保留或重新计算真实多边形重叠。

最终验收资产应重新烘焙。旧资产可按内部材质名兼容原有 Voronoi 切面，但不能因此宣称旧模型的全部跨构件暴露面已经正确。

## 网格材质

外表面采用基于米制位置的程序化材质，无需 UV。所有碎块共用统一建筑坐标原点和方向，不能按各碎块质心重新起格；本演示建筑根保持单位缩放。

| 参数 | 已实现默认值 |
| --- | --- |
| 小格边长 | 0.2m，用户明确要求 |
| 大格边长 | 1.0m，即每 5 小格，用户明确要求 |
| 小格线宽 | 约 0.8 屏幕像素，细且较浅 |
| 大格线宽 | 约 1.8 屏幕像素，更粗且更深 |
| 表面底色 | 浅灰，避免强反光掩盖格线 |
| 抗锯齿 | 使用屏幕导数控制线边平滑，远处稳定退化 |

格距按米，线宽按屏幕像素以适应自由移动时的观察距离变化。1m 线与小格线重合时以大格样式覆盖，不重复叠加变黑。

墙面使用由建筑竖直方向和未扰动几何法线构成的面内正交基；水平楼板使用建筑水平轴。这样斜向竖墙的面内格距也是真实 0.2m，而不是把世界投影距离误当作表面边长。对共面碎块保持同一基与相位。

采用 `ExtendedMaterial<StandardMaterial, ...>` 保留 PBR 光照。网格与断面可为同一扩展的两种模式或两个明确材质类型，具体拆分在实现时以代码清晰度和共享绑定验证。

## 自由相机与显示

- 采用垂直视场角 60°、近裁剪面 0.05m、远裁剪面 500m 的透视相机。初次加载时位于运行时 +Z 侧朝 -Z，高度对齐建筑包围盒中心；按包围盒及窗口宽高比只取景一次，约留 15% 边距。窗口尺寸变化只更新透视长宽比，不重置相机位姿，粒子也不触发重新取景。
- WASD 使用相机局部前后左右方向，前进/后退随俯仰方向飞行；Space 和左右 Ctrl 分别沿世界 +Y / -Y 移动。合并输入后归一化，以 6m/s 运动，避免斜向叠加提速。移动按实际帧时间积分，无相机碰撞或重力。
- 鼠标转向灵敏度为每运动像素 0.002 弧度；相对鼠标位移不再乘帧时间。航向绕世界 Y 轴、俯仰限制在 ±89°，相机不滚转。
- 获得控制时锁定并隐藏鼠标，屏幕中央显示准星；Tab 释放/重新锁定。鼠标释放或窗口失焦时暂停移动与转向；失焦后由一次点击恢复控制，该次点击不执行破坏。Esc 保持退出功能。
- 使用斜向主光和适量环境补光，让凹凸断面和建筑深度可读；烟尘为半透明，不作为点击目标。

## 0 键调试线框

主键盘 `Digit0` 切换，兼容数字小键盘 `Numpad0`；按下沿触发一次，持续按住不反复切换。

普通模式保持完整 Grid 外观。调试模式叠加橙色预破碎边界，保留表面和深度遮挡，不默认透视全部内部线。

导入时合并同一 Chunk 的全部 primitive，在位置容差下焊接重复顶点，构建三角面邻接；移除同一平面内的三角化对角线，保留真正折角与边界。边数据缓存，删除碎块同步移除其线，不每帧重新分析网格。

首选 Gizmos 或专用线段绘制，保留深度测试并施加轻微深度偏移。普通 GPU triangle wireframe 会显示三角化对角线，且 polygon line 模式存在后端限制，不作为用户所需 fracture 线框的默认实现。

## 左键破坏

1. 鼠标锁定时，由当前自由 Camera 将屏幕中央准星位置转换为世界射线，使用 Avian 查询最近存活的建筑 Collider；忽略地面、特效和已删除状态。释放鼠标时的点击只恢复控制。
2. 命中 Chunk 必定删除。默认可扩展到命中点附近、同一受击表层的直接邻接碎块，建议半径 0.4m、上限 6 块；具体值为可调演示参数。
3. 扩展选择以真实表面距离和受击面深度带约束，不能沿射线穿过前墙连删背墙，也不能只按碎块质心距离选择。
4. 将目标立即标记 Removed，删除/隐藏它的全部显示 primitive 与 debug 边，取消实例内 incident Bond，并在物理安全边界移除 Collider。查询过滤同步排除 Removed，避免固定步数据尚未更新时再次命中旧碰撞体。
5. 在真实命中点和暴露面产生特效。剩余碎块保留原有封闭面，其朝向被删块的内部面自然暴露，不再生成平面封住新洞。

所有操作基于导入的预定义碎块；本轮不运行网格切割，也不因为图失支撑而让整栋楼坍塌。

## 断面与 VFX

断面使用材料物理类别对应的程序化颗粒噪声、颜色变化、高粗糙度和高度梯度法线扰动。混凝土使用厘米级骨料与更细孔隙两层尺度；法线扰动带来近景凹凸感。

这是材质层面的凹凸，实际预切轮廓、接触图、质量和碰撞不变。仅提高 roughness 不足以表达凹凸，也不在此轮对相邻切面独立位移，以免完整建筑提前露缝。

VFX 分为短促的向外碎屑爆发、缓慢上升扩散的烟尘和快速消散的细粉。烟尘使用随当前相机朝向更新的柔边公告板，装饰碎屑使用少量共享网格；固定种子可用于重放验收。首版采用 Bevy 原生 ECS/共享材质和网格，不依赖尚未核验 0.20 兼容性的额外粒子库。

特效有总数、生命周期和连续点击预算，不无限累积；装饰粒子不加入建筑连接图，也不创建永久物理障碍。除预算外，不额外同步删除已存在的建筑碎块来制造视觉效果。

## 建议代码边界与交付顺序

| 模块 | 责任 |
| --- | --- |
| `asset` | 结构清单/GLB 依赖、校验与稳定 ID 绑定 |
| `scene` | BSN 场景、Chunk 实例、初始相机与灯光 |
| `camera` | 自由移动、鼠标转向、捕获状态、首次取景与准星 |
| `material` | 米制 Grid、WESL PBR 扩展及断面 |
| `interaction` | 射线命中、局部选择、实例删块事务 |
| `debug` | fracture 边缓存、0 键开关与深度线绘制 |

资产表面角色及接触分类先独立提交；BSN 导入、材质、线框、点击和特效作为可运行的完整演示一起验证、提交。模块边界保持如上。

## 备选方案与取舍

- 运行时任意切割：能生成更自由的破口，但超出本轮按预定义碎块删除的目标，并增加碰撞重建和封口成本；采用已有预破碎资产。
- 直接实例化完整 glTF 场景后遍历改造：可以保留更多原场景关系，但需要额外处理节点位姿、primitive 分组和运行时组件补挂；本轮使用 glTF 原始资源加 BSN 声明，保持 Chunk 身份和删除边界明确。
- 为每块烘焙独立网格纹理：依赖 UV，容易跨块错位；本轮采用统一建筑坐标下的程序化 Grid。
- 原生三角线框与实际切面位移：前者含多余对角线，后者可能让完整建筑提前露缝；分别采用几何边提取和材质法线凹凸。若之后要求断面轮廓本身起伏，再单独设计匹配的切面几何与碰撞更新。

## 验收与未决问题

1. 导入矩形、L 形与庭院资产，Chunk 数、primitive 数、位姿和碰撞与 Blender 输出一致；错误哈希拒绝加载。
2. 墙和楼板格距精确为 0.2m/1m，跨碎块连续；大线更粗更深，远处无明显锯齿或闪烁。
3. 相机初次加载覆盖整个模型；WASD 移动、鼠标转向、Space / Ctrl 升降有效，斜向速度与帧率不改变移动速率，俯仰不翻转。移动后等待、窗口变化和新增实例均不重置位姿。失焦/释放鼠标时停止控制，恢复控制的点击不破坏建筑。
4. 0 键单次切换；普通模式不露预破碎线，调试模式可看边界且无三角化对角线。
5. 点击只破坏命中位置附近的预定义碎块，所有 primitive、Collider、debug 边和实例状态同步移除；一次点击不穿透前墙删除背墙。
6. 删除相邻不同 Part 的碎块后，所有新暴露接触区域为粗糙断面，原来可见的外表面仍为 Grid；门窗洞口保持通行。
7. 烟尘和粒子从命中处出现、按时消失；连续点击后对象数量受上限控制。
8. 在完整资产上保存初始视角、自由移动后、切换调试和点击后的截图进行视觉比较，并实际编译和运行；转向后准星射线正确，烟尘公告板仍朝向相机。完成范围按下方实施记录中的证据判断。

BSN 组合、glTF 新材质类型、WESL 绑定与深度线绘制已完成编译和运行验证。后续颜色和视觉参数变化需同步更新本记录；大规模性能、动态坍塌与结构承载仍不在本轮验收范围。

## 实施记录（2026-11-17）

### 已完成：资产表面语义与重新烘焙

- Blender 工具版本 0.2.0 为材料输出 `extras.bd_surface_role = exterior | fracture`，保留原物理材料 ID。
- 根据真实源 Part 的反向共面凸多边形交集划分接触补丁，并将其边界插入碎块显示网格；仅覆盖区域为 fracture，部分接触面剩余区域保留 exterior。
- 接触分割只调整显示拓扑和材质。凸代理、质量、连接数据不改变；对数值重复点采用 1µm 容差焊接，并重新验证封闭性、体积、质心与 GLB 哈希。
- 已重新生成 `assets/buildings` 下的 rectangle（255 Chunk / 849 Bond / 44 Anchor）、l_shape（482 / 1686 / 71）、courtyard（353 / 1183 / 50）。
- Blender 5.2.3 LTS 后台验证通过：geometry 5 项、fracture 5 项、asset_tool 9 项、surfaces 6 项、bundled_surfaces 3 项，共 28 项；0.2.0 ZIP 隔离安装、启用与停用另行通过。涵盖部分接触、分离补丁保留缝隙、斜面、预破碎补丁、共享角点去重及固定种子显示拓扑一致性。
- 对三个实际导出 GLB 的 exterior 三角形面积求和，与“源构件总表面积减去所有真实接触补丁双侧面积”独立核对，在源表面积的百万分之一容差内一致，避免接触多边形重复首点使整片接触漏分类。

### 已完成：原演示运行时实现（历史记录，提交 7e3c6bb）

- `asset` 以正式 GLTF 依赖加载 `.destruction.json`，校验米制 Y-up、稳定 ID、引用、有限数据、质量/惯性、节点 extras/位姿及 GLB SHA256；全部 primitive 和碰撞准备成功后才生成整栋建筑。持续扫描待生成实例，支持资产加载后新增实例。
- `scene` 使用 `bsn!` 组合相机、灯光、建筑根、Chunk 根、所有显示 primitive 及提示。清单位姿只应用一次；保留质量、完整惯性、锚点和实例内连接状态。每块为静态 Avian 凸代理，不模拟坍塌。资产根目录采用构建时仓库 `assets`，不依赖可执行文件所在目录。
- `material` 采用官方 glTF 材质转换及 WESL PBR 扩展，统一建筑坐标下使用 0.2m / 1m 格距、0.8px / 1.8px 线宽；斜墙采用正交面内基。断面按所属 Chunk 物理材料类别选择颜色、粗糙度和厘米骨料/细孔噪声，使用高度梯度扰动法线。
- `debug` 跨 primitive 按 0.00001m 容差焊接，细分 T 接点后剔除共面对角线，缓存几何边；橙线宽 1.4px，深度偏移 -0.00002，仍保持深度遮挡。主键盘及小键盘 0 均按按下沿切换。
- `interaction` 从相机鼠标射线查询最近存活 Collider，必删命中块；仅扩展到直接 Bond 邻块，真实表面距离不超过 0.4m、深度带 0.08m、法线点积至少 0.7，每次最多 6 块。立即标记 Removed、删除全部 primitive 和调试边并取消 incident Bond；下一 `FixedUpdate` 移除 Collider / RigidBody，早于 Avian `FixedPostUpdate`，旧碰撞查询同步通过存活状态排除。
- `vfx` 在命中点及新暴露连接面附近生成每次最多 64 个装饰粒子，总数上限 640；使用共享公告板柔边纹理、碎屑网格及 16 档消散材质。碎屑 0.7–1.3s、烟尘 1.8–2.5s、细粉 0.35–0.8s；不加入连接图或创建 Collider。预算满时抑制后续生成，现有粒子正常到期回收。
- 固定相机位于运行时 +Z 侧朝 -Z，正交取景按窗口长宽比留 15% 边距，禁用视角操纵。正常运行使用实际时间，验证模式使用确定的 1/60s 时间步以避免刷新率影响检查。

## 自由视角修订（2026-11-17）

- 状态：已采用；已实现并完成以下验证。
- 背景：用户要求自由飞行以观察建筑各面和破口，原固定正视相机限制了观察范围。
- 决策：采用上方“自由相机与显示”的透视相机、6m/s 移动、鼠标 0.002rad/px、±89° 俯仰限制和捕获状态控制。建筑只在首次加载时决定初始视图；左键通过中央准星破坏，烟尘公告板随相机旋转。
- 备选与取舍：保留正交投影可维持原展示比例，但前后移动缺少透视反馈；绕建筑轨道旋转便于展示，却不能满足 WASD 自由飞行。采用无重力、无相机碰撞的飞行方式，允许检查建筑内部；新增角色行走/碰撞时应另记设定。
- 验证要求：覆盖六向移动、相反输入抵消、合成速度归一化、帧时间积分、鼠标灵敏度与俯仰边界；检查只取景一次、失焦与 Tab 的捕获切换、恢复控制不误删；在引擎中转向、移动并以准星破坏，确认特效朝向与既有删块/预算回归。
- 实施：新增 `camera` 模块控制透视相机，移除每帧正视重置；准星射线使用 `TransformHelper` 读取当帧最新位姿，恢复鼠标捕获的点击被消费。烟尘/细粉公告板在相机控制后更新旋转，装饰碎屑保留自旋。
- 自动验证：`cargo test` 共 19 项通过；其中相机 6 项覆盖运动方向、斜向限速、帧率独立、俯仰边界、失焦、Tab/点击捕获、窗口变化及晚加入实例不重置位姿；VFX 回归增加转向后公告板方向检查。格式检查、`cargo clippy --all-targets -- -D warnings` 和实际构建通过。
- 引擎验证：三种建筑均完成 `output/free-camera/{rectangle,l_shape,courtyard}` 下五张截图及报告。运行中执行合成移动、往返转向和横向位移，再以鼠标转向瞄准、从屏幕中心发射破坏射线；`camera_flight_checks=true`，首次分别删除 5 / 2 / 4 块并各生成 64 粒子，粒子峰值 639（上限 640），最终均为 0，全部检查通过。截图确认透视深度、准星、控制提示、斜向观察破口和烟尘显示。
- 验证边界：控制键、失焦及光标捕获状态由 ECS 输入回归验证；图形检查使用引擎预定输入，未使用桌面自动化。以上记录替代旧固定相机的控制验收，原历史数据保留。
- 未决问题：后续是否增加移动速度或灵敏度设置；本次采用上述默认值，不增加行走模式或滚轮调速。
